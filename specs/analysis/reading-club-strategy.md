# Strategy: Reading Pal for Reading Clubs

**Date**: 2026-06-13

---

## Context

The app is solid as a personal reading tracker, but that space is saturated
(Goodreads, StoryGraph). To differentiate, the focus is casual reading clubs —
recreational groups for people discovering literary works, not academic circles.

---

## Key Insight

A casual reading club has very specific dynamics that no existing app addresses well:

- People don't want to feel judged — they want to have fun
- Some members read everything, some read half, some read nothing (and nobody admits it)
- The meeting is the social event; the book is the pretext
- New readers need scaffolding: they don't know what to ask, what to look for, how to engage

---

## Differentiating Ideas

### 1. Shared Clubs
Create or join a club. A shared book of the month. See each member's reading progress
(without pressure — just an avatar with a % indicator). Vote on the next book.

### 2. AI-Generated Discussion Questions (Gemini)
"Generate 5 discussion questions for chapters 1–10 of this book, for a casual group."
The facilitator has questions ready before the meeting. Strong differentiator for groups
without an expert moderator.

### 3. Spoiler-Safe Progress Mode
Quotes and comments are tagged with how far the poster has read. Nobody sees content
beyond where they've reached.

### 4. Reactions on Quotes
Club members can react to quotes others have shared (🔥😂😢🤯).
Social without being a social network.

### 5. Milestone Celebrations
Animation when someone finishes the book of the month. Notification to the club:
"[Name] finished the book!" Gentle, positive gamification.

### 6. "Catch Up" (AI)
Button for members who haven't read: a summary of the chapters they should have read
this week, generated by Gemini. Discreet, no shame.

## Technical Feasibility

The existing stack handles all MVP requirements without adding new paid services:

| Need | Solution | Status |
|------|----------|--------|
| Member authentication | Firebase Auth (Google) | ✅ Already configured |
| Shared real-time database | Firestore `onSnapshot` | ✅ Already installed |
| AI discussion questions | Gemini Flash | ✅ Already integrated |
| AI memory capsule | Gemini Flash | ✅ Same client |
| Gamification / badges | Client-side logic on Firestore data | ✅ No backend needed |
| New UI screens | React + MUI | ✅ Existing stack |

**Main architectural shift**: The personal tracker is "local-first" (Dexie as source of truth).
Club data must be "Firestore-first" since it is shared across users. Both patterns coexist
in the same app — personal books stay in Dexie; club data lives entirely in Firestore.

---

## Recommended Next Steps

1. **AI Discussion Questions** — fast to implement, very concrete for the use case.
   Reuses the existing Gemini infrastructure.
2. **Shared Clubs** — structural feature that changes the app model from personal to social.
   Requires a new Firestore data model (clubs, memberships, book of the month).
